사기 탐지 — 엔드투엔드 머신러닝 시스템

금융 거래의 사기 위험을 평가하는 프로덕션 수준의 머신러닝 시스템으로, 합성 데이터 생성부터 학습, 서빙되는 REST API, 모니터링 대시보드, 드리프트 탐지, 자동 재학습까지를 다루며 전체 과정을 MLflow로 추적하고 Docker로 컨테이너화했습니다. 데이터셋은 시연을 위해 합성으로 생성된 것이며, 이 모델은 실제 금융 데이터로 학습되지 않았으므로 실제 사기 판단에 사용해서는 안 됩니다.

Python FastAPI scikit-learn MLflow Streamlit SQLAlchemy Docker Compose pytest / GitHub Actions
GitHub →

개요

이 프로젝트는 하나의 사용 사례를 중심으로 완전한 MLOps 라이프사이클을 구현합니다: 금융 거래의 사기 위험 평가. 노트북 속 모델에서 멈추는 대신, 이 시스템은 모델을 둘러싼 모든 것 — 실험 추적, 챔피언/후보 별칭을 사용하는 모델 레지스트리, 비용을 고려한 임계값 선택, 예측 로깅, 드리프트 모니터링, 자동 재학습 트리거 및 파이프라인, 그리고 로컬 또는 Docker Compose로 실행 가능한 배포용 API와 대시보드까지 다룹니다.

문제

사기 탐지 모델은 실무에서 가장 중요한 축인 비용 기준으로 평가되는 경우가 드뭅니다. 기본값인 0.5 결정 임계값으로 조정되거나 정확도만으로 평가된 모델은, 놓친 사기 건과 오탐이 서로 매우 다른 비즈니스 비용을 갖는다는 사실을 놓치기 쉽습니다. 모델 자체를 넘어서, 사기 스코어링 서비스는 실험을 재현 가능하게 추적하고, 새 모델을 안전하게 승격시키고, 실시간 예측을 로깅 및 모니터링하고, 재학습이 필요할 만큼 입력 데이터가 드리프트했는지 감지할 방법도 필요합니다 — 이는 독립된 노트북 모델이라면 전혀 다루지 않는 문제들입니다.

솔루션

이 시스템은 합성 거래 데이터를 생성하고, 이를 검증 및 프로파일링한 뒤, 피처 세트를 구성하고, 모든 실행을 MLflow에 기록하며 분류기(기본값: 로지스틱 회귀)를 학습합니다. 고정된 0.5 컷오프 대신, 결정 임계값은 기대 비용(expected cost)을 최소화하도록 선택되며, 기본값으로 놓친 사기 건은 오탐보다 20배 더 무겁게 가중치가 부여됩니다. 선정된 모델은 MLflow 모델 레지스트리에 champion 별칭으로 등록되고, FastAPI 엔드포인트를 통해 사기 확률, 위험 등급, 판정 결과와 함께 해당 예측에 가장 크게 기여한 피처들을 반환합니다. 모든 예측은 SQLite에 기록되고, 드리프트 감지기는 실시간 트래픽을 기준 데이터셋과 비교하며, 규칙 기반 트리거가 재학습 파이프라인 실행 여부를 결정합니다 — 이 파이프라인은 새 후보 모델이 현재 챔피언 대비 명시된 PR-AUC, 비용, 재현율 마진을 충족할 때만 이를 승격시킵니다.

아키텍처 / 워크플로우

합성 데이터 → 검증 → 피처 엔지니어링 → 학습 + MLflow 추적 → 비용 기반 임계값 → 모델 레지스트리 → FastAPI 서빙 → 모니터링 + 드리프트 → 자동 재학습

FastAPI는 /predict, /model/info, /monitoring/summary, /health 엔드포인트를 제공합니다. Streamlit 대시보드의 예측 및 모니터링 페이지는 API를 실시간으로 호출하며, 모델 성능 및 드리프트/재학습 페이지는 data/results/*.json 리포트를 직접 읽습니다. MLflow 추적 서버는 API 및 대시보드와 함께 실행되어 실험 추적과 모델 레지스트리를 담당하며, 동일한 mlflow.db와 mlruns/ 파일을 공유하지만 실제 서빙 경로에서는 벗어나 있습니다 — API는 시작 시 등록된 모델을 로드하므로 추론 시점에 MLflow가 떠 있어야 할 필요가 없습니다. 오프라인 파이프라인 — scripts/ 아래 단계별 CLI 스크립트를 Makefile 타깃으로 감싼 구조 — 은 합성 데이터를 생성하고, 피처를 구성하고, MLflow를 통해 모델을 학습 및 평가하고, 이를 등록하며, API와 대시보드가 읽는 드리프트 및 모니터링 리포트를 생성합니다. 세 서비스(API, 대시보드, MLflow UI)는 모두 공유 네트워크 상에서 Docker Compose로 함께 실행되며, 데이터와 아티팩트는 리포지토리에서 바인드 마운트되어 컨테이너 출력이 호스트에서도 보입니다.

결과 / 영향

0.965 ROC-AUC (테스트 세트)
94.8% 사기 포착률 (재현율)
14.7% 선택된 임계값에서의 검토율
0.524 PR-AUC (테스트 세트)

기준 로지스틱 회귀 모델을 기대 비용을 최소화하는 임계값(0.48)에서 홀드아웃 테스트 세트로 평가한 결과, 위 재현율 및 검토율 수치와 함께 정밀도 0.197을 기록했습니다. 비용 함수에서 놓친 사기 건이 오탐보다 20배 더 무겁게 가중치가 부여되기 때문에, 최적 운영 지점은 정확도를 극대화하는 대신 정밀도보다 재현율을 의도적으로 우선시합니다 — 정상 거래의 약 15%를 검토 대상으로 표시하는 대가로 사기의 거의 95%를 포착합니다.

구현 내용

  • 실시간으로 거래를 스코어링하고 비용 최적화된 임계값에서 사기 확률, 위험 등급, 승인/검토 판정을 반환하는 FastAPI 서비스
  • 챔피언/후보 별칭을 사용하는 MLflow 기반 실험 추적 및 모델 레지스트리
  • 0.5를 기본값으로 사용하는 대신 기대 비용을 최소화하는 비용 기반 임계값 선택, 위양성/위음성 비용 가중치 설정 가능
  • 선형 모델을 위한 예측별 설명 가능성 — 영향 방향(increases_risk / decreases_risk)을 포함한 주요 기여 피처
  • 물량, 지연 시간, 검토율, 위험 등급 분포를 모니터링하는 SQLite 기반 예측 로그
  • 기준 데이터셋과 실시간 트래픽 간 드리프트 감지(수치형 피처는 상대 평균 이동, 범주형 피처 및 위험 등급은 총변동 거리)
  • 규칙 기반 재학습 트리거와, 후보 모델이 PR-AUC, 기대 비용, 최소 재현율에서 현재 챔피언을 능가할 때만 승격시키는 재학습 파이프라인
  • 예측, 모델 성능, 모니터링, 드리프트/재학습을 위한 전용 페이지를 갖춘 Streamlit 대시보드
  • 린팅, 테스트, 이미지 빌드를 위한 pytest 스위트와 GitHub Actions CI/CD를 갖춘 3-컨테이너 Docker Compose 스택(API, 대시보드, MLflow UI)

어려웠던 점

  • 정확도나 고정된 0.5 컷오프 최적화 대신 실제 비즈니스 비용 비대칭을 반영하는 임계값 선택 목표 설정
  • 혼합된 수치형·범주형 피처 전반에서 작동하면서도 해석 가능한(평균 이동 대 총변동 거리) 드리프트 지표 설계
  • 재학습된 후보가 미미하거나 노이즈성 개선만으로 챔피언을 대체할 수 없을 만큼 엄격한 승격 기준 정의
  • MLflow 추적/레지스트리 계층을 실제 서빙 경로와 분리하여, API가 추론 시점에 MLflow 가동 여부에 의존하지 않도록 유지
  • 새로운 모델 변형이 코드 변경이 아니라 새 YAML 파일이 되도록 오프라인 파이프라인을 독립적인 설정 기반 CLI 단계로 구조화

배운 점

사기 모델을 만드는 것은 오히려 쉬운 부분이며, 진짜 엔지니어링 노력은 그 주변 시스템을 구축하는 데 들어갑니다. 임계값 선택을 정확도 목표가 아니라 비용 최소화 문제로 프레이밍한 것은 어떤 모델 동작이 "좋다"고 간주되는지를 바꾸었고, 재현율/정밀도 트레이드오프를 암묵적인 것이 아니라 명시적이고 설정 가능한 결정으로 만들었습니다. 재학습을 수동으로 학습 스크립트를 다시 실행하는 것이 아니라 — 드리프트 신호, 모니터링 지표, 엄격한 승격 기준을 갖춘 — 통제된 파이프라인으로 다루는 것이야말로, 시간이 지나도 프로덕션에 유지할 만큼 신뢰할 수 있는 모델을 실제로 만들어냅니다.
